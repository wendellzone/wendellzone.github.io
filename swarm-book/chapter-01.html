从零理解 Agent

不写一行代码，我们先把三个绕不开的词——LLM、function calling、Agent——用大白话彻底讲明白。

本章目标

  • 知道 LLM（大语言模型）到底是什么、它的"输入输出"长什么样。
  • 理解一个致命局限：LLM 只会"说话"，不会"做事"。
  • 搞懂 function calling（函数调用）如何给 LLM 装上"手脚"。
  • 明白 Agent（智能体） = LLM + 工具 + 说明书 + 一个不停转的循环。

一、LLM：一个只会"接话"的超级大脑

你一定用过 ChatGPT。它背后的东西叫 LLM（Large Language Model，大语言模型）。抛开所有数学，你只需要记住它的本质：

类比：接龙高手

LLM 就像一个读遍了全世界文字、极其擅长"文字接龙"的大脑。你给它一段话，它就猜下一个最合理的词，一个接一个地往下写，直到写完。它不"知道"真相，只是把话接得极其像人。

在程序里，我们和 LLM 打交道的方式非常固定：我们发一份消息列表过去，它回一条新消息。消息列表里每条消息都有一个"角色（role）"：

  • system（系统）：给 LLM 定规矩、设定人设。好比员工入职时发的岗位说明书。
  • user（用户）：真人说的话。
  • assistant（助手）：LLM 自己回的话。

这个"发一串消息、收一条回复"的过程，官方叫 chat completion（对话补全）。整个流程如下图：

二、致命局限：它只会"说"，不会"做"

现在问题来了。假设你问 LLM："纽约现在天气怎么样？"

它会非常自信地回答你——然后编一个数字。因为它根本没法查实时天气：它没有联网、没有传感器、不能运行代码，它只能生成文字。

核心痛点

LLM 就像一个被关在密室里、知识渊博但手脚被绑住的天才。你问它任何需要"动手查/算/操作"的事，它都只能靠想象力硬编。这就是我们需要"function calling"的原因。

三、function calling：给大脑装上"手脚"

function calling（函数调用）是现代 LLM 的一项关键能力。它的思路非常巧妙：

我们提前告诉 LLM："嘿，你身边有几个工具可以用，比如一个叫 get_weather(location) 的函数能查天气。" 于是当你再问"纽约天气如何"时，LLM 不会瞎编，而是回复一句特殊的话："请帮我调用 get_weather，参数 location='NYC'。"

注意——LLM 自己并不会执行这个函数。它只是"点单"。真正跑代码的是我们的程序。程序跑完，把结果（比如"67°F"）再喂回给 LLM，LLM 这才用人话组织出最终回答。整个配合像这样：

类比：点菜的顾客

LLM 像餐厅里的顾客：它不进厨房，只会看着菜单（工具列表）说"我要这道菜（调用这个函数）"。厨房（我们的程序）把菜做好端上来，顾客再决定下一句话怎么说。

四、Agent：把这一切装进一个"会自己转的循环"

有了 function calling，还差最后一块拼图。因为一次问答可能要调用好几次工具：查完天气，可能还要查穿衣建议，再查交通……总不能每次都靠人手动把结果喂回去。

于是我们写一个循环：只要 LLM 还在"点单"（还想调用工具），程序就自动执行、自动把结果喂回去，再问 LLM 一次——直到 LLM 说"我不用工具了，这是最终答案"为止。这个"打包好"的东西，就是 Agent（智能体）。

Agent 的极简定义

Agent = 一份岗位说明书（system prompt） + 一个工具箱（functions） + 一个自动循环（不停地"问 LLM → 执行工具 → 再问"）。
这正是 Swarm 框架帮你做的事。后面我们会看到，这个"循环"就藏在 core.py 的 run() 函数里（第 07 章的主角）。

把它翻译成一个"带工具箱的员工"的画面，就非常好懂了：

  • 岗位说明书（instructions / system prompt）：告诉员工"你是谁、该干什么"。
  • 工具箱（functions）：员工能动用的具体本领，比如查天气、查数据库。
  • 大脑（LLM）：员工的思考与决策中枢。
  • 循环（run loop）：员工"思考 → 动手 → 再思考"的工作节奏，直到把活干完。

五、多个 Agent 协作：Swarm 名字的由来

一个员工能力有限。真实系统里常常有一群各有专长的员工：接待员、售后专员、翻译……当接待员发现"这事我搞不定"，就把顾客转接给对应的专员。这种"转接"在 Swarm 里叫 handoff（交接）（第 06 章详讲）。

一群会互相转接、协同工作的 Agent，就像一窝分工明确的蜜蜂——这就是 Swarm（蜂群 🐝） 这个名字的由来。

常见疑问

LLM 真的"理解"我的意思吗？

严格说，它是在做极其精妙的"文字接龙"，本质是概率预测，而非人类式的理解。但对我们写程序来说不必纠结哲学问题：只要它的输出足够可靠好用即可。重要的是记住它会一本正经地编造，所以关键信息要靠工具去查真数据。

function calling 是 LLM 自己"偷偷"跑了我的代码吗？

不是。这是本章最容易误解的点。LLM 永远不会执行你的代码，它只会返回"我想调用哪个函数、参数是什么"这样一段结构化文字。执行代码的始终是你的程序（在 Swarm 里就是 core.py 里的 handle_tool_calls）。这也是为什么它相对安全、可控。

那 Agent 和直接调 ChatGPT 有啥区别？

直接调 ChatGPT 是"一问一答"，问完就结束。Agent 多了两样：工具（能真正查/算/操作）和循环（能自动多轮调用工具直到完成任务）。所以 Agent 能完成"查天气 → 根据天气给建议 → 帮你订提醒"这种需要多步动手的任务。

本章小结

  • LLM 是个只会"文字接龙"的大脑：输入一串消息，输出一条回复，但不会动手做事。
  • function calling 给它装上手脚：LLM 负责"点单"（说要调哪个函数），程序负责"做菜"（真正执行），再把结果喂回去。
  • Agent = 说明书 + 工具箱 + 自动循环，把上面这套配合打包起来，能自主完成多步任务。
  • 多个会互相 handoff（交接） 的 Agent 协作，就是 Swarm（蜂群）。
