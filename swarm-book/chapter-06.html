Agent 交接 handoff

一个 Agent 搞不定？那就把活儿转给更专业的同事。本章拆开 Swarm 最优雅的设计——交接，不需要任何特殊 API，只要让一个普通工具函数 return 一个 Agent。

本章目标

  • 理解什么是 handoff（交接），以及它为什么是"蜂群协作"的关键。
  • 逐行读懂 agent_handoff.py：两个 Agent + 一个"转接工具"。
  • 搞懂框架内部靠哪三步，把"当前 Agent"从英语切换到西语。
  • 记住核心设计之妙：交接 = 让普通工具函数返回一个 Agent 对象。

一、类比：前台的一次"转接电话"

想象你打电话到一家跨国公司的客服。接起电话的是前台接线员。你一开口是西班牙语，前台听不太懂，于是他说："请稍等，我帮您转接西语专员。"——"咔哒"一声，电话被转到了会西班牙语的同事那里，接下来由这位专员和你继续对话。

类比：转接电话

handoff（交接）就是这次"转接电话"。前台接线员 = 英语 Agent；西语专员 = 西语 Agent。前台发现"这活儿该转给专员"，就按下转接键，把你交给了对的人。
关键在于：通话没有中断，你之前说过的话专员也都听得到——只是从这一刻起，回你话的人换了。

在 Swarm 里，这一整套"转接"动作，写起来只需要一个普普通通的函数。我们这就来看真代码。

二、前置概念：Agent 也能当"返回值"

回顾第 04 章：Agent 有一个 functions（工具箱），里面装着一堆可以被 LLM "点单"调用的函数。以前我们的工具函数都是返回一个字符串（比如查到的天气"67°F"）。

本章的关键突破点是：工具函数还可以返回一个 Agent 对象。当框架发现"哦，这个工具返回的不是字符串，而是另一个 Agent"，它就明白了——"这是要交接！"于是它把"当前负责说话的 Agent"换成返回的那一个。就这么简单。

一句话记住

普通工具返回字符串 → 框架把它当"数据"喂回给 LLM。
工具返回 Agent → 框架把它当"交接指令"，切换当前 Agent。

三、逐行精读 agent_handoff.py

这是 Swarm 官方示例里最短、也最能体现设计哲学的一个文件。我们一段段拆。

examples/basic/agent_handoff.py 
from swarm import Swarm, Agent

client = Swarm()

english_agent = Agent(
    name="English Agent",
    instructions="You only speak English.",
)

spanish_agent = Agent(
    name="Spanish Agent",
    instructions="You only speak Spanish.",
)


def transfer_to_spanish_agent():
    """Transfer spanish speaking users immediately."""
    return spanish_agent


english_agent.functions.append(transfer_to_spanish_agent)

messages = [{"role": "user", "content": "Hola. ¿Como estás?"}]
response = client.run(agent=english_agent, messages=messages)

print(response.messages[-1]["content"])

下面逐块解释。

① 造两个 Agent：英语专员、西语专员

两个 Agent 
english_agent = Agent(
    name="English Agent",          # 名字：英语 Agent
    instructions="You only speak English.",   # 岗位说明书：你只说英语
)

spanish_agent = Agent(
    name="Spanish Agent",          # 名字：西语 Agent
    instructions="You only speak Spanish.",   # 岗位说明书：你只说西语
)

这里我们造了两个员工：一个只会说英语，一个只会说西语。它们的"人设"就写在 instructions（岗位说明书 / system prompt）里。目前它们互不相干，谁也不认识谁。

② 关键：一个"返回 Agent"的转接工具

转接工具函数 
def transfer_to_spanish_agent():
    """Transfer spanish speaking users immediately."""
    return spanish_agent      # ← 注意！返回的是一个 Agent 对象，不是字符串

这就是全场最关键的一行。transfer_to_spanish_agent 表面上是个普通函数，但它 return 的是 spanish_agent ——一个 Agent 对象。

还要特别留意函数的那句英文文档字符串（docstring）："Transfer spanish speaking users immediately."（把说西语的用户立刻转接走）。这句话不是写给人看的注释——它会被 Swarm 提取出来，当作"这个工具是干嘛的"说明，发给 LLM 看。LLM 正是靠读懂这句话，才知道"遇到西语用户就该点这个工具"。

别小看 docstring

工具函数的 docstring 就是给 LLM 的"工具使用说明书"。写得越清楚，LLM 越知道什么时候该调用它。如果留空，LLM 就只能靠函数名瞎猜了。

③ 把转接工具"装进"英语 Agent 的工具箱

装配工具 
english_agent.functions.append(transfer_to_spanish_agent)

还记得第 04 章说过，Agent.functions 是一个列表（工具箱）吗？这里我们把 transfer_to_spanish_agent 追加进英语 Agent 的工具箱。

于是英语 Agent 现在有了一个新本领："我可以把用户转接给西语专员。" 注意西语 Agent 自己并没有这个工具——它只管说西语，不负责转接。

④ 用西班牙语提问，看它怎么反应

发起对话 
messages = [{"role": "user", "content": "Hola. ¿Como estás?"}]   # 用户用西语打招呼
response = client.run(agent=english_agent, messages=messages)   # 从英语 Agent 起手

print(response.messages[-1]["content"])   # 打印最后一条回复

我们从英语 Agent 起手（agent=english_agent），但用户上来就是一句西班牙语 "Hola. ¿Como estás?"（你好，你好吗？）。

接下来发生的事，就是本章的高潮：英语 Agent 一看"这是西语，我说不了"，于是它调用了工具 transfer_to_spanish_agent()，工具返回 spanish_agent，框架当场把"当前 Agent"切换成西语 Agent，由西语 Agent 用西班牙语回答用户。最后 response.messages[-1] 拿到的，就是西语 Agent 说的那句西班牙语。

四、框架内部：三步完成"切换当前 Agent"

你可能会好奇：我明明只是让函数 return 了一个 Agent，框架怎么就"自动切换"了？答案藏在 core.py 里，一共就三步。（下一章我们会把整个 run() 拆到骨头，这里先看和交接相关的三步。）

第 1 步：识别"返回值是个 Agent" → 打包成 Result

core.py · handle_function_result 
def handle_function_result(self, result, debug) -> Result:
    match result:
        case Result() as result:          # 如果本来就是 Result，原样返回
            return result

        case Agent() as agent:            # ★ 如果返回值是一个 Agent
            return Result(
                value=json.dumps({"assistant": agent.name}),  # 塞一条说明性文字
                agent=agent,              # ★ 把这个 Agent 记在 Result.agent 里
            )
        case _:                           # 其它情况（字符串、数字……）
            try:
                return Result(value=str(result))   # 转成字符串塞进 value
            except Exception as e:
                ...

Swarm 用 Python 的 match 语句给工具返回值"分类归一化"。当它匹配到 case Agent()——也就是我们的 transfer_to_spanish_agent() 返回了一个 Agent——它就构造一个 Result 对象，并把这个 Agent 塞进 Result.agent 字段。这一步等于给框架打了个标记："用户想切到这个 Agent。"

第 2 步：把这个"想切换的 Agent"往上传递

core.py · handle_tool_calls（节选） 
result: Result = self.handle_function_result(raw_result, debug)  # 拿到归一化的 Result
partial_response.messages.append({ ... })     # 把结果作为一条 tool 消息记录下来
partial_response.context_variables.update(result.context_variables)
if result.agent:                              # ★ 如果 Result 里带着一个 Agent
    partial_response.agent = result.agent     # ★ 就把它记到本轮的"待切换 Agent"

handle_tool_calls 负责真正执行工具。执行完拿到 Result 后，它检查 if result.agent:——如果这次工具调用带回了一个 Agent，就把它记录到 partial_response.agent，相当于把"要切换"的信号继续往主循环传。

第 3 步：主循环真正换人

core.py · run（节选） 
partial_response = self.handle_tool_calls( ... )   # 执行工具，可能带回一个 Agent
history.extend(partial_response.messages)          # 工具结果并入对话历史
context_variables.update(partial_response.context_variables)
if partial_response.agent:                         # ★ 如果本轮要切换
    active_agent = partial_response.agent          # ★ 把"当前 Agent"换成新的！

active_agent 是主循环里那个"当前负责说话的 Agent"变量。这里一句 active_agent = partial_response.agent，就把它从英语 Agent 换成了西语 Agent。下一轮循环再问 LLM 时，用的就是西语 Agent 的说明书和工具箱了——转接完成！

设计之妙

整个交接没有任何专门的"handoff API"。框架只是约定："工具函数如果返回一个 Agent，就切过去。" 一个再普通不过的 return，配合上面三步串联，就实现了 Agent 之间的自由转接。少即是多，这就是 Swarm 的优雅所在。

常见疑问

工具返回一个 Agent，和返回一个字符串，到底有啥区别？

区别全在框架怎么"解读"这个返回值：

  • 返回字符串（比如 "67°F"）：框架把它当作"工具查到的数据"，作为一条 role="tool" 的消息喂回给当前这个 Agent，让它继续用这份数据组织回答。当前 Agent 不变。
  • 返回 Agent（比如 return spanish_agent）：框架在 handle_function_result 里识别出这是个 Agent，于是把 active_agent 切换成它。从下一轮起，换人回答。

一个是"给数据"，一个是"换人",这就是全部差别。

交接之后，之前的对话历史还在吗？西语 Agent 看得到用户之前说的话吗？

历史是连续的，全都在，一条都不会丢。 Swarm 内部只有一份对话历史 history，从头到尾不断往里追加消息。交接只是换了"当前负责说话的 Agent"（active_agent 变量），并不会清空或重置历史。

所以西语 Agent 接手后，能看到用户最初那句 "Hola. ¿Como estás?"，也能看到英语 Agent 调用转接工具的记录。就像转接电话——线路没断，专员能听到你之前说的话。这正是"无缝转接"的体验来源。

转接是单向的吗？西语 Agent 能再转回英语 Agent 吗？

完全可以，只要给西语 Agent 也装一个"转回英语"的工具即可，例如：

def transfer_back_to_english(): return english_agent，然后 spanish_agent.functions.append(transfer_back_to_english)。

这样两个 Agent 就能互相转接。更进一步，你可以造一个"分诊台（triage）Agent"，让它掌握所有"转接到 X 专员"的工具，根据用户问题分派给不同专员——这就是构建多 Agent 系统的常见套路。

本章小结

  • handoff（交接） = 把当前对话转交给另一个更合适的 Agent，就像前台把电话转接给专员。
  • 实现交接不需要任何特殊 API：只要写一个普通工具函数，让它 return 一个 Agent 对象。
  • 把这个转接工具用 agent.functions.append(...) 装进负责"起手"的 Agent，LLM 会在合适时机自己调用它。
  • 框架靠三步完成切换：handle_function_result 识别出返回值是 Agent 并打包进 Result.agent → handle_tool_calls 传递到 partial_response.agent → run() 主循环 active_agent = partial_response.agent 真正换人。
  • 对话历史全程连续，交接只是"换了回话的人"，用户之前说过的话新 Agent 都看得到。
